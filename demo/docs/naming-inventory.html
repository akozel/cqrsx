Инвентарь имён витрины

Все компоненты и термины, через которые проходит событие после коммита и до документа в MongoDB: в библиотеке cqrsx, в базах и в демо. У каждого имени: за что оно отвечает, насколько понятно читателю кода и что предлагается. Имена сверены с кодом на 25 октября 2026 года.

Инвентарь
78 строк по 8 этапам пути. Большинство имён однозначны и подходят.
Конфликты смыслов
Одиннадцать слов значат разное в разных местах кода: settle, worker, dispatch, lock и lease, ledger, replay и rebuild, version, last_sequence, stale и stalled, event, page.
Русские слова
«Закладка» в интерфейсе значит и снимок агрегата, и закладку проекции; второе значение я добавил в этом тикете, исправить стоит до коммита. «Лента» в документах эпика значит и чтение журнала, и SSE.

Конфликты смыслов

Правила словаря

Чтобы конфликты не появлялись снова, одно слово — один смысл во всём проекте: в коде, хранилищах, документах и интерфейсе.

  1. Lock значит только замок агрегата в памяти. Любое владение на срок — lease, в коде и в полях хранения.
  2. Settle значит только записать итог задачи outbox.
  3. Worker значит только исполнитель задач outbox. Очередь ключа в доставке — lane.
  4. Rebuild значит пересборку документа; replay не используется после тикета 05.
  5. Journal — таблица событий целиком. Ledger — только доменный журнал фаната.
  6. Version — только версии схем (event_version, task_version). Счётчик записей документа — revision.
  7. Page без уточнения — страница журнала в событиях. Для других единиц единица входит в имя.
  8. Event в имени типа — только доменное событие.
  9. Два имени, отличающиеся одной-двумя буквами, не значат разное: RebuildRequest/RebuildRequests, stale/stalled.
  10. По-русски: снимок — snapshot, закладка — checkpoint, лента — только SSE, журнал — events.

Порядок переименований

Предлагаю четыре шага от дешёвого к дорогому. Проект не выпущен, поэтому совместимость не нужна; хранилища пересоздаются через make reset.

1. Внутри cqrsx, без смены API

Только внутренние имена процессора и доставки.

  • turn → step
  • settle() → advance_completed(), settling() → failure_due()
  • dispatch() → hand_out(), frontier → read_position
  • Context → ProcessorContext, Bounded → WriteLimit, Worker → KeyLane

2. Публичный API cqrsx

Ломающие изменения, но вызывающих мест мало.

  • settle → wake_delay (добавлено сегодня, дешевле всего)
  • rebuild_page → rebuild_keys_per_page, concurrency → max_concurrent_writes
  • RebuildRequest → RebuildRequestOutcome, RebuildRequests → PendingRebuilds, take_requests → take_rebuild_requests, request_rebuild_key → request_key_rebuild
  • RebuildEvent → RebuildPhase, LeaseEvent → LeaseChange, LedgerTotals → JournalTotals
  • по желанию: Position → FeedPosition, ViewContext → ViewMeta с полем view_id

3. Поля хранения

Меняют схемы; нужен make reset.

  • закладки: lock_token, locked_until → lease_token, lease_until; applied → events_read
  • документы витрин: version → revision
  • outbox: те же lease-поля, если применять правило 1 полностью; это самая большая правка

4. Демо и интерфейс

Переменные, ответы API, тексты.

  • ENCORE_REPLAY_* → ENCORE_REBUILD_*, SETTLE_MS → WAKE_DELAY_MS, BUFFER → KEY_BUFFER
  • статус: stale → from_cache
  • RebuildService → ReadSideService, EventLedgerStats → JournalStats, ReadModelStore → ReadModelQueries
  • UI: снимок вместо «закладки» для snapshots, лента только для SSE

Источник: код рабочего дерева ветки perf/postgres на 25 октября 2026 года, тикет 03/04 не закоммичен. Строки «внутренний» и «внутри крейта» не видны пользователям библиотеки; их переименование не ломает API.
