## Станет

1. **Образы:** `e06-base` (задача 01: движок и demo `a270a06` с каталогом `demo/load/epic06/` поверх) и `e06` из
   коммита задачи 07 (`demo/load/epic06/perf/build.sh e06 <журнал> <коммит>`), оба с модулем `probe`.
2. **Точки и способ** — как в задаче [01](01_baseline_measurement.md): шесть конфигураций
   `demo/load/epic06/perf/series.plan` (серия не дольше 40 минут), `REPEAT=3`, порядок перемешан в каждом проходе,
   каждый прогон не дольше 5 минут, во время серии ничего не собирается.
3. **Подсчёт аллокаций** (`demo/load/epic06/allocations`) на коммите задачи 07 против таблицы «до».
4. **Сравнения:**
   - `compare.mjs … e06-base- e06- --md` — CPU бэкенда на 1 000 команд и задач, принятых/с, p50/p99, слив задач;
   - `statements.mjs` — разница множеств текстов SQL пуста;
   - `GET /api/config` обоих образов — одинаковый JSON; список имён `ENCORE_*`/`OUTBOX_*` одинаков (кроме
     `ENCORE_LOAD_*` задачи 01, они есть в обоих).
5. **Что решает:** CPU на операцию не хуже «до» ни в одной точке; принятых/с — в пределах разброса; операторов SQL на
   команду — равно. Расхождение хуже — дефект одной из задач: найти, исправить, повторить точку.

## Этапы

1. Образ `e06`; проверочные прогоны `REPEAT=1`.
2. Серия; сравнения; таблица «до → после» с медианами, min–max и Δ.
3. Итог эпика: README («Где мы сейчас», статусы), `PROGRESS.md`, пометка в отчёте аудита, что исправлено и что
   отклонено.
4. Удалить каталог `demo/load/epic06/` целиком (`git rm -r`), когда числа «после» записаны: в нём синтетический
   модуль, подсчёт аллокаций, сценарий k6 и скрипты серий эпика. Проверить, что на него не ссылается ничего, кроме
   документов эпика: `grep -rn 'epic06\|ENCORE_LOAD\|/api/probe' --exclude-dir=docs --exclude-dir=results
   --exclude-dir=target` по `cqrsx`, `cqrsx-macros`, `demo` пуст (само слово `probe` есть в тестах cqrsx и в
   `Cargo.lock` demo — это не следы эпика); образы `encore-load-backend:e06*` и результаты `e06*` в `demo/load/results` — удалить или оставить по
   решению пользователя.
