## Сейчас

JSON ходит через дерево `serde_json::Value`:
- **чтение:** sqlx разбирает текст столбца `json` в `Value`, потом `serde_json::from_value` превращает его в структуру
  (`serialized_event.rs:118`, `:125`; снапшот — `persisted.rs:593`);
- **запись:** структура → `Value` (`serialized_event.rs:98–99`, `persisted.rs:534`) → текст в sqlx.

Каждое дерево — сотни мелких выделений памяти. Для зала на 40 мест снапшот — 2–5 КБ JSON. Команда читает снапшот,
события после него (в среднем 4.5) и метаданные каждого события. Процессор разбирает так же каждое событие страницы.

## Станет

Разбор прямо из текста столбца: `sqlx::types::Json<…>` или `Box<RawValue>` в `SerializedEvent` и
`SerializedSnapshot`, `serde_json::from_str` в типизированное событие и агрегат. `Value` строится только тогда, когда
подходит upcaster: он по-прежнему получает изменяемое дерево. Запись — `serde_json::to_string` прямо из структуры.

## Зачем, на примере

Бронь на горячем концерте под блокировкой разбирает снапшот зала дважды (текст → дерево → структура), а при записи
снапшота каждое десятое событие собирает дерево и потом текст. После правки — по одному проходу в каждую сторону.

## Риски

- **Публичные типы меняются.** `SerializedEvent::payload`, `metadata` и `SerializedSnapshot::aggregate` — часть
  контракта `PersistedEventRepository` и upcaster-ов. Обратная совместимость не нужна, но API должен остаться
  понятным: upcaster работает с `Value`, репозиторий — с текстом.
- **Выигрыш может оказаться в шуме.** Тогда правка не вливается: решаем по цифрам.

## Как измерить

`02b-spread-vus50` и `01-hot-key-vus40`, профиль `app`, «до» и «после» вперемешку, `REPEAT=3`: CPU бэкенда на 1000
команд, принятых в секунду. На горячем ключе ещё удержание блокировки (задача 14, если она сделана).

## Критерии приёмки

- [ ] События и снапшоты читаются и пишутся без промежуточного `Value`; upcaster получает `Value` только когда
      подходит.
- [ ] Тесты: upcaster на чтении и в пересборке, несовместимый снапшот, метаданные; матрица фич зелёная.
- [ ] Замер записан в тикет; правка вливается, только если CPU бэкенда на команду заметно ниже.
