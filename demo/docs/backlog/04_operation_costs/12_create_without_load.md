## Сейчас

Анонс концерта загружает агрегат, которого нет: снапшот (пусто), события после 0 (пусто), CTE записи. В `02a` профиля
`db` предел — PostgreSQL: 174–197 % из 200 % в прогонах `perf-db-*05-02a-*` (`a747f06`), около 7.3 тыс. анонсов/с.
Два из трёх операторов не находят ни одной строки, но платят полную цену оператора.

## Станет

Команда, которая создаёт поток, не загружает агрегат. Она решает на `A::default()` с номером 0, а коммит пишет
событие № 1 с обычной проверкой. Если поток уже есть, вставка события № 1 конфликтует. Тогда команда идёт обычным
путём: загрузка и решение. Домен отказывает «концерт уже анонсирован», как и сейчас. Повтор после такого конфликта —
без паузы политики повторов: это не гонка, а неверное предположение.

Кто объявляет команду созданием, решает план. Два варианта:
- **агрегат:** `fn creates(command: &Self::Command) -> bool { false }` в `Aggregate`, `Concert` отвечает `true` для
  `AnnounceConcert`;
- **use case:** отдельный вызов исполнителя.

Первый держит знание в домене («анонс начинает концерт») и не требует от приложения помнить об оптимизации.

## Зачем, на примере

Организатор анонсирует тур: 300 концертов за минуту. Сейчас на каждый — три обращения к базе, два из них заведомо
пустые. После правки — одно.

## Риски

- **Решение на пустом состоянии** должно совпадать с решением на загруженном пустом потоке. Это верно по построению:
  загрузка пустого потока и даёт `A::default()`.
- **Под блокировкой агрегата** конфликт может прийти только от другой ноды или от уже существующего потока.
- **Снапшот при создании.** Интервал снапшота 1 означает снапшот уже на событии № 1. Проверка версии снапшота
  (`next_version = 1`, вставка) должна дать конфликт так же, как вставка события.

## Как измерить

`02a-announce-vus100`, `db`, wrk, «до» и «после» вперемешку, `REPEAT=3`:
- анонсов/с;
- операторов и CPU PostgreSQL на анонс;
- p99.

Затем `full`: куда переходит предел (MongoDB или бэкенд).

## Критерии приёмки

- [ ] Команда создания пишет событие № 1 без чтения; существующий поток даёт обычный путь и прежний ответ домена.
- [ ] Тесты: `MemStore`, PostgreSQL; создание существующего потока; создание со снапшотом на первом событии; две
      ноды создают один поток одновременно — одна команда принята, вторая отказана доменом.
- [ ] Демо: `AnnounceConcert` объявлен созданием.
- [ ] `components.md`, README cqrsx; замер записан в тикет.
