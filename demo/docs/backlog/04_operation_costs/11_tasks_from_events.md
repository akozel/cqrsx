## Сейчас

Задачи привязываются к команде до её выполнения. `FrameworkFactory::framework(tasks)` (`executor.rs:16–27`) вызывается
«once per command, before its first attempt», а задачи едут в репозиторий outbox при его создании. Задаче отмены
нужны данные из истории: id брони и сумма возврата. Поэтому демо читает концерт до команды
(`cancel_booking.rs:59`, `self.history.load_aggregate`).

Что это стоит:
- два оператора (снапшот и события после него) и разбор снапшота на каждую отмену, вне блокировки;
- на горячем ключе отмена — половина команд: 20 581 загрузка против 15 806 коммитов за окно, то есть −9 550
  операторов из 86 167 (11 %) после правки;
- между предварительным чтением и коммитом есть окно, в которое другая команда может изменить бронь.

При этом событие `BookingCancelled` несёт всё, что нужно задаче `encore_record_cancellation`: место, фаната, id брони,
id отмены и возврат (`domain/concert/events/booking_cancelled.rs`).

## Станет

Второй способ передать задачи — функция от решённых событий. Она вызывается после `handle` на каждой попытке, внутри
блокировки и до коммита. Задачи коммитятся с событиями, которые их породили. Эскиз:

```rust
// cqrsx: what a command commits with its events
pub enum CommandTasks<A: Aggregate> {
    /// Known before the command runs (today's `Vec<NewTask>`).
    Fixed(Vec<NewTask>),
    /// Built from the events the attempt decided; a failure refuses the command before the commit.
    FromEvents(Box<dyn Fn(&[A::Event]) -> Result<Vec<NewTask>, TaskValidationError> + Send + Sync>),
}
```

Где считать задачи, решает план. Два места:
- **(а)** `CqrsFramework` после `handle` передаёт задачи в `EventStore::commit`. Задачи становятся частью коммита, а
  фабрика больше не получает их заранее (`FrameworkFactory::framework()` без аргумента).
- **(б)** Хранилище с outbox получает функцию и вызывает её в `commit` на типизированных событиях.

Вариант (а) проще объяснить: задачи — часть записи, как метаданные. Демо строит `encore_record_cancellation` из
`BookingCancelled`; бронь может остаться на `Fixed`: её задача строится из команды.

## Зачем, на примере

Фанат отменяет бронь места A1. Сейчас касса сначала читает весь концерт, чтобы узнать, сколько вернуть, потом ставит
команду в очередь блокировки и читает концерт ещё раз. После правки читает один раз — под блокировкой, а сумма
возврата берётся из события, которое агрегат только что решил записать.

## Риски

- Функция задач не должна обращаться наружу: она выполняется внутри блокировки. Правило — в документации
  `CommandTasks::FromEvents`.
- Ошибка функции (невалидная задача) — отказ команды до коммита, как сейчас `Executed::tasks_unavailable`.

## Как измерить

`01-hot-key-vus40`, `db` и `app`, «до» и «после» вперемешку, `REPEAT=3`:
- загрузки агрегата равны коммитам;
- операторов на команду −11 %;
- CPU бэкенда и PostgreSQL на команду;
- принятых в секунду.

- [ ] Исполнитель принимает задачи заранее или функцией от событий; функция вызывается на каждой попытке, и
