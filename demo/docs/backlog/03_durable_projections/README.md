# Эпик 03. Надёжные проекции

[← все эпики](../README.md)

Источник: обсуждение 2026-10-24 «EventSourcing → Projection: как у Axon и что делать в cqrsx». Сейчас проекции
обновляются обработчиками исполнителя команд после коммита, в памяти процесса и без гарантии доставки: падение
процесса или сбой MongoDB между коммитом и записью витрины теряет обновление до следующего Encore!, а Encore!
(`EventReplay`) — второй, отдельный механизм. Эпик заменяет оба одним: проекция сама читает журнал от своей
закладки, а replay — это сдвиг закладки. Так устроены Axon (tracking token), Marten (event progression),
EventStoreDB (persistent subscriptions) и Akka Projections (offset store).

## Принцип

Журнал уже переживает падения; для проекций не хватает порядка чтения и закладки.

1. **Позиция.** Каждое событие запоминает номер транзакции, которая его записала (`events.tx xid8`, умолчание
   `pg_current_xact_id()`). Читатель берёт события с номером больше закладки и меньше горизонта снимка
   (`pg_snapshot_xmin(pg_current_snapshot())`): всё ниже горизонта завершено, поэтому дыр нет — читатель не
   пропускает, а ждёт. Внутри агрегата порядок по `tx` совпадает с порядком по `sequence`.
2. **Закладка.** Строка `projection_checkpoints` на пару «проекция + тип агрегата»: позиция, аренда владельца,
   состояние replay. Пишет её только владелец аренды, короткими запросами; во время записи в MongoDB никакие
   блокировки базы не держатся.
3. **Процессор.** Цикл «продлить аренду → прочитать страницу → разложить по ключам в `OrderedDelivery` →
   дождаться квитанций → сдвинуть закладку до события перед первым сбоем; при сбое пауза с ростом». Replay тем
   же циклом: владелец видит запрос, чистит витрину, ставит позицию 0 и `replay_until`.
4. **Непрерывность документа.** Документ витрины хранит `last_sequence` и принимает только событие
   `last_sequence + 1`: более старые пропускаются, дыра — ошибка. Поэтому доставка «хотя бы раз», перехват аренды
   и повторное чтение после падения не портят витрину.

## Что гарантируем

| # | Гарантия | Чем обеспечена | Где проверяется |
|---|---|---|---|
| G1 | Событие, попавшее в журнал, будет применено к каждой проекции своего типа — при падении процесса, ноды, MongoDB или PostgreSQL | закладка остаётся ниже события, пока оно не применено; горизонт снимка исключает пропуски | [03](03_projection_processor.md) «Модель сбоев» |
| G2 | Внутри агрегата события применяются по порядку, без пропусков и повторов | порядок `tx` = порядок `sequence`; непрерывность документа | [01](01_contiguous_views.md), [02](02_event_position.md) |
| G3 | Документ витрины всегда равен свёртке непрерывного префикса событий своего агрегата — при любом числе нод и перехватах аренды | `last_sequence` + CAS по версии; fencing закладки по `lock_token` | [01](01_contiguous_views.md), [03](03_projection_processor.md) F5, F19 |
| G4 | Сбой не пропускает событие молча: проекция останавливается на нём, и это видно | закладка не двигается за сбой; `failures`, `last_error`, отставание в статусе | [03](03_projection_processor.md) F6–F8, [04](04_demo_on_processor.md) |
| G5 | Replay не останавливает запись и идёт тем же кодом | `replay_requested` → владелец: wipe, позиция 0, `replay_until`; у коллекции один писатель | [03](03_projection_processor.md) F14–F17, [04](04_demo_on_processor.md) |
| G6 | Путь записи не дорожает | колонка с умолчанием и одна запись в индекс; ни одной лишней строки на команду | замер в [02](02_event_position.md) и [04](04_demo_on_processor.md) |

## Общие правила

- Одна задача — один коммит: `feat(cqrsx): <что>; adopt in demo` (с `!`, если API ломается) или
  `feat(demo): <что>`. Агент не коммитит по своей инициативе: оставляет готовое рабочее дерево и предлагает
  сообщение коммита и список файлов.
- Покрытие `cqrsx` не ниже 97 %, матрица фич из корневого `CLAUDE.md`; ядро процессора компилируется без
  `postgres`.
- Изменение схемы (`cqrsx/sql/`) идёт с ассетом обновления для существующих баз и тестом этого ассета.
- Каждое настраиваемое значение — константа умолчания в cqrsx и переменная `ENCORE_*` в демо. Режимов и
  переключателей не добавляем.
- В логах нет идентификаторов агрегатов и содержимого событий (как в `diagnostics`).
- Нагрузочный замер — против серии `perf-08b-` эпика 02 на стенде `demo/load`, `VERIFY=1` в каждом прогоне.
  Запущенный dev-стек пользователя не трогаем.

## Вне рамок

- Сегменты по хешу идентификатора агрегата (одна проекция на нескольких нодах параллельно): добавляются колонкой
  `segment` в ключ таблицы закладок, когда одной ноды не хватит.
- Dead-letter на ключ (как у Axon): больной агрегат паркуется, остальные идут дальше. Пока сбой останавливает
  проекцию и виден.
- Общий читатель журнала на тип агрегата для нескольких проекций: пока процессор на проекцию.
- Пересборка в соседнюю коллекцию с переключением в конце (blue/green).
