## Сейчас

[revisit.md](revisit.md) — первоначально 16 тем: `apply` по значению; upcasting; маршрутизация `Decide` + derive; одно событие на
команду; `Rejection` в домене; `#[command_id]`; внутренние команды и `cqrs.execute` против `ctx.execute`; подписи
ленты; форма обработчика задачи; версии контракта задачи; политика у типа задачи против выбора при постановке;
запросы к витринам; своя реализация витрины под каждую базу (открытый вопрос 06/1); перестройка без LWW под
нагрузкой; дерево модулей (03); наблюдатель задач в движке с заметками обработчика (08).
В задачах 11–12 добавлены темы 17–26; подготовленный обзор охватывает все 26 тем.

## Станет

Разбор с пользователем по темам, с кодом демо и cqrsx перед глазами:
1. По каждой теме — «оставить» или «изменить», с одной фразой почему; запись в `revisit.md` (столбец «Решение»,
   дата).
2. Для «изменить» — тикет: в этом эпике, если правка меньше задачи среднего размера и не ломает требование 1; иначе —
   в следующем эпике.
3. Темы 13 (витрина под каждую базу) и 14 (перестройка под нагрузкой: `02b-spread-vus50` с `VERIFY=1` и две ноды
   `NODES=2 BALANCE=key` из 13) — с цифрами стенда.
4. Исключения из требования 1, накопленные в задаче 01 (`concert_id`/`fan_id`, общий обработчик), перечитываются:
   остаются ли они исключениями или становятся правилом документации.
5. Эпик закрывается: README эпика — итог, бэклог `README.md` — строка эпика; законченные документы удаляются по
   правилу бэклога (`design/` уже переехал в 14; тикеты остаются как история эпика, пока пользователь не решит иначе).

## Этапы

1. Подготовить по каждой теме одну страницу: как получилось, где удобно, где нет, что показали цифры.
2. Разбор с пользователем, решения в `revisit.md`.
3. Тикеты по решениям; закрытие эпика.

## Зачем, на примере

Тема 11: политика привязана к типу задачи при регистрации (`.task(issue_refund).policy(MAIL)`). Альтернатива —
выбор при постановке (`then.task(x).policy(MAIL)`) с именем политики в метаданных задачи; она отклонена при
построении бэклога, но нужна ли политика для отдельной постановки — видно только на коде после 09 и 11.

## Риски

- **Пересмотр превращается в новый эпик.** Правило 2: мелкое — здесь, крупное — отдельным эпиком с собственным
  бэклогом.

## Как проверить

- `revisit.md`: у каждой темы решение с датой; каждое «изменить» — ссылка на тикет.

## Поведение не меняется: чем доказано

Разбор кода не меняет; тикеты по его итогам доказывают неизменность своими разделами.
