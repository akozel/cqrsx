- **Все задачи, хеш в `status.md`.** Хеш коммита задачи не может попасть в тот же коммит: строка задачи в коммите
  несёт «(этот коммит)», хеш вписывается сразу после коммита и уходит в коммит следующей задачи. Между задачами в
  дереве изменён только `status.md`.
- **03, отступления от карты переезда** (записываются в карту тикета 03 и в пути тикетов 08, 09, 12):
  `fan/domain/fan.rs` вместо `fan/domain/aggregate.rs` (симметрия с `concert/domain/concert.rs`); HTTP-тесты маршрутов —
  `bootstrap/routes/tests.rs`, а не `operations/presentation/tests.rs` (собирают маршруты всех модулей);
  `workflows.rs` (`ChainStep`, `run_chain_step`, `map_fan_outcome`) — `fan/application/chain.rs`, а не
  `shared/application/chain.rs` (код называет `Fan`/`FanApp`); `PostgresLedger` — `bootstrap/ledger.rs` (порт
  `operations` и оба агрегата). Исключения И-1…И-7 в `tests/architecture.rs` — у каждого причина и задача, которая
  его снимает; тест падает на неиспользованном исключении.

- **04, сверх тикета** (утверждено в плане): `COPY cqrsx-macros` в `demo/back-end/Dockerfile` и `demo/sidecar/Dockerfile`
  (иначе образы стенда и dev-стека не собираются); presentation может называть только `cqrsx::cqrs::rejection`
  (allowlist `tests/architecture.rs`: ответ 422 зовёт `code()`/`params()`); в корне cqrsx — четыре derive и скрытый
  `__private` (`serde_json` для развёртки); проверки контрактов при сборке (пустые имя/версия/код, версия задачи > 0,
  повтор кода).

- **05, рабочая копия только при планировщике** (В-1, записывается в «Станет» тикета 05 и в `components.md`): тикет
  описывал `after = committed.clone(); after.apply(event.clone())` безусловно; копия нужна только `Decision::after`,
  поэтому без планировщика её нет. С планировщиком (демо, стенд) операции попытки те же, без него — на три меньше и
  ни одной новой; наблюдаемый результат тот же. Многособытийные и «пустые» команды тестов cqrsx переписаны (инвентарь —
  в тикете 05); 12 тестов переименованы, имена которых стали неправдой.

- **07, `#[label]` у задачи** (В-1, вариант «а»): поле переезжает из тела в метаданные при `NewTask::new` и
  возвращается адаптером при разборе — как требует дизайн 05 («в метаданные, а не в тело»); при пустом `LABELS` путь
  задачи тот же. Сверх тикета: `cqrsx::task::DEFAULT_MAX_ATTEMPTS = 10` вместо литерала; имена контрактов `…V1` пока
  остаются (конструкторы `SendETicketV1::of`, `IssueRefundV1::of`).

- **08, лента и presentation** (В-1, В-3): `fan_id` записей команд книжки берётся из id книжки (`FanOf` в
  `operations`), а не из `#[label]` — у команд книжки нет поля фаната (тема 8 пересмотра); presentation может называть
  `cqrsx::cqrs::command::{CommandExecutor, CommandGatewayError}` — обработчик сам отдаёт команду движку (до 11/12).
  Наблюдатель команд — отдельный тип `CommandActivityObserver`. Порядок отчётов одного ключа — порядок коммитов, кроме
  вытеснения потока между отпусканием блокировки и вызовом (сегодня окно шире).

- **09, обработчики задач** (утверждено в плане): таблица исходов шагов (G-22) сохраняется у обоих обработчиков целиком,
  как сегодня `map_fan_outcome` (отклонён вариант «у каждого своя таблица», менявший исход недостижимых веток);
  `ctx.execute` отвечает `CommandGatewayError` (без `ExecuteFailed`); привязка политик — в `bootstrap::tasks::policies`
  до 11; `CommandMetadata` переезжает в cqrsx, presentation может называть его; пять тестов фабрики диспетчеров уходят
  вместе с ней (исключение 01); `TaskContext` без параметра времени жизни (`Arc` попытки).
