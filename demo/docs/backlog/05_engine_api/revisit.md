# Темы для пересмотра после реализации

Сюда попадают решения, принятые до реализации «пока», с оговоркой вернуться к ним. Перед закрытием эпика проходим
список вместе с пользователем и по каждой теме решаем, оставить решение или изменить. Это последняя задача эпика.

| # | Тема | Что решили | Что оценить | Откуда |
|---|---|---|---|---|
| 1 | `apply`: событие по значению или по ссылке | по значению: домен без `.clone()`, одна копия события на команду внутри движка | читаемость `apply`, цена копии на горячем ключе | [design/02](design/02_aggregate.md), 2026-10-26 |
| 2 | Старые версии событий (upcasting) | отложено: новое поле добавляется со значением по умолчанию | нужен ли перевод старых версий и в каком виде | [design/02](design/02_aggregate.md), 2026-10-26 |
| 3 | Маршрутизация команд | `Decide<A>` на каждой команде и `#[derive(Commands)]` на enum | удобство по сравнению с явным `match`: читаемость, ошибки компилятора, навигация по коду | [design/03](design/03_commands.md), 2026-10-26 |
| 4 | Одна команда — одно событие | ровно одно событие или отказ (D-02) | нужен ли список событий; связь с групповой записью (04/17) | [design/03](design/03_commands.md), 2026-10-26 |
| 5 | Коды отказов для API | `#[derive(Rejection)]` на ошибке домена: код — вариант в snake_case, параметры — его поля | удобство; не нарушает ли это границы компонентов: коды для HTTP живут в домене. | 9 | Обработчик задачи | функция с `#[task_handler]`, зависимости — её параметры, корень модуля подключает их через `.provide(..)` | удобство; альтернативы: отдельный тип с полями-зависимостями (`impl TaskHandler`); метод самой задачи с зависимостями из контекста по типу | [design/05](design/05_tasks.md), 2026-10-26 |
