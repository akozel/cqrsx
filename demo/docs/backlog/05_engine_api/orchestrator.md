## Цикл одной задачи

Задачи идут строго по порядку номеров: 02, 03, …, 15. Следующая не начинается, пока предыдущая не принята и не
закоммичена. Для каждой задачи NN:

### 1. Бриф

Прочитай тикет `NN_*.md`. Напиши `work/NN-brief.md` по шаблону из раздела «Шаблон брифа» и запусти суб-агента:
инструмент `Agent`, `subagent_type: "general-purpose"`, `model: "opus"`, `effort: "xhigh"`,
`description: "Epic 05 ticket NN"`, `prompt` — содержимое брифа. Суб-агент работает в фоне; жди уведомления, не
опрашивай и не гадай о результате. Пока он работает, ничего не собирай и не тестируй сам.

### 2. План

Суб-агент пишет `work/NN-plan.md` и останавливается. Проверь план против тикета (разделы «Станет», «Этапы»,
«Критерии приёмки», «Поведение не меняется»), дизайна, строк guarantees.md и правил README эпика:
- каждый критерий приёмки покрыт конкретным шагом и тестом;
- названы тесты, которые добавляются, переезжают и переименовываются; переименования попадут в guarantees.md;
- есть доказательство неизменности поведения: какие строки G-xx держат какие тесты, какие эталоны должны
  совпасть;
- нет обхода правил: без `#[ignore]`, без ослабления утверждений, без снижения порогов, без обратной
  совместимости и алиасов, без новых режимов;
- отступления от тикета или дизайна названы явно, с причиной.

Ответ суб-агенту — через `SendMessage` тому же агенту (контекст сохраняется): «План утверждён» или замечания
списком, записанные также в `work/NN-plan-review-rK.md`. На план — не больше двух кругов; после второго утверждай
его со своими поправками, перечислив их.

Отступление от дизайна или тикета решаешь ты. Принимай его, если сохраняются требования пользователя (README
эпика, задача 01) и гарантии; запиши в `status.md` в раздел «Отступления» с причиной и поручи суб-агенту обновить
тикет или файл дизайна. **Изменение поведения движка (любая строка guarantees.md, тексты SQL, форматы, имена
переменных, действующие значения) не принимается никогда.** Если задача невыполнима без него — запиши в
`status.md` «заблокировано: нужно решение пользователя», не коммить ничего, и остановись, потому что следующие
задачи зависят от этой.

### 3. Реализация

После утверждения суб-агент делает работу, прогоняет все проверки, пишет `work/NN-report.md` и
`work/NN-checks.log`. Он не коммитит. Дождись отчёта.

### 4. Приёмка

Проверяй сам, не доверяя отчёту на слово:
1. **Дерево.** `git status --short`: только ожидаемые пути; никаких файлов из `work/`, временных файлов, правок
   `.env`; lockfile'ы изменены только если менялись зависимости. `git diff --stat` сходится с отчётом.
2. **Проверки.** Прогони сам, вывод в `work/NN-checks.log` (дописывай, `tee -a`):
   - корень: `cargo fmt --all --check`; `cargo clippy --locked --workspace --all-targets --all-features -- -D warnings`;
     `RUST_TEST_THREADS=2 PROPTEST_RNG_SEED=42 cargo test --locked --workspace --all-features`; матрица:
     `cargo test --locked -p cqrsx --no-default-features`, затем `--features postgres`, `worker`, `host`, `logging`,
     `mongodb` (и `http` после задачи 12); `cargo llvm-cov --locked --workspace --all-features --fail-under-lines 97`
     и `cargo llvm-cov --locked -p cqrsx --all-features --fail-under-lines 97`;
   - демо (`cd demo`): `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test`;
   - инструменты стенда, если менялись: `node --check`, `bash -n`.

   Две проверки покрытия можно не повторять, если в `work/NN-checks.log` суб-агента есть их результат с
   процентами ≥ 97 и файл журнала новее любого изменённого файла (`git diff --name-only`, сравни mtime).
   Задача, которая не трогает cqrsx (03, 13, 14, 15), требует только проверок демо и инструментов. Известные
   случайные сбои: doctest'ы могут упасть с `E0463 can't find crate` сразу после пересборки библиотеки — повтори
   один раз; порог покрытия на грани из-за одного случайного теста — повтори один раз, не снижай.
3. **Критерии приёмки** тикета — по одному, с уликой: имя теста в выводе или `grep` по файлу, строка в
   `components.md`, обновлённая строка guarantees.md (старых имён тестов не осталось: `grep` по ним), пустой
   `git diff` эталонов `demo/back-end/tests/golden/` после задачи 02.
4. **Поведение не меняется** — строки G-xx из тикета: их тесты прошли без изменения утверждений (сверь дифф этих
   тестов, если они правились), эталоны совпали.
5. **Отчёт полон:** список файлов, результаты проверок, соответствие каждому критерию, отступления, что осталось.

Замечания — списком в `work/NN-review-rK.md` и тем же списком суб-агенту через `SendMessage`; он исправляет и
присылает новый отчёт; ты проверяешь заново (пункты 1–5 целиком). Не больше трёх кругов.

### Когда задача не принимается за три круга

Решай сам и продолжай, по порядку:
1. новый суб-агент с точным брифом только на оставшиеся замечания (запусти его так же, с `effort: "xhigh"`);
2. мелкое доделай сам (правка на несколько строк, документ, переименование) и прогони проверки;
3. прими с записанным отступлением — только если все проверки зелёные и гарантии держатся.

Что запрещено всегда: пропустить задачу, выключить или удалить тест ради прохождения, снизить порог, оставить
проверки красными, закоммитить непринятое.

### 5. Коммит и статус

Принятую задачу коммить сам, один коммит на задачу, без push, без `--amend` прошлых коммитов:
- `git add` только файлов задачи и `demo/docs/backlog/05_engine_api/status.md`; `work/` не добавлять;
- сообщение по правилам README эпика: `refactor(cqrsx): <что>; adopt in demo` для задач с cqrsx,
  `refactor(demo): <что>` для задач только про демо, `test(demo): …` для 02, `perf(load): …` или `docs(backlog): …`
  для 13, `docs(…)` для 14 и 15; тело — что сделано и чем доказана неизменность; последняя строка —
  `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`;
- в тикете поставь статус «сделано <дата>» и короткий «Результат» (суб-агент пишет его в отчёте — перенеси);
  в README эпика обнови строку таблицы и, после 13, раздел «Где мы сейчас»;
- `status.md`: строка задачи — «принято», хеш коммита, число кругов, дата; запись в журнал.

Перед запуском следующей задачи убедись, что `git status --short` пуст (кроме `work/`).
